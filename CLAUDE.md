This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal portfolio site for Van Zachary Singco — a Vue 3 + Vite + TypeScript + Tailwind v4 single-page app built on **shadcn-vue**, deployed to GitHub Pages (`VanSingco/vansingco.github.io`).

Note: `README.md` is the unmodified Vue/Vite scaffold README. It is not a source of truth for this project.

## Commands

```sh
npm run dev         # Vite dev server
npm run build       # vue-tsc --build, then vite build
npm run type-check  # vue-tsc --build
npm run build-only  # vite build, no type-check
npm run preview     # serve dist/ locally
```

There is no test runner and no lint script. `vue-tsc --build` is the only automated gate.

## Deployment

GitHub Pages serves the **`gh-pages` branch root** (verified via the Pages API: `build_type: legacy`, `source.branch: gh-pages`). There is no Actions workflow — publishing means getting the *contents* of `dist/` onto `gh-pages`.

`dist/` is listed in `.gitignore` but force-added and **tracked on `main`** as well; a change is not live until `dist/` is rebuilt. `vite.config.ts` sets `base: './'` so built asset URLs stay relative. `public/.nojekyll` stops Jekyll from eating hashed asset filenames.

## Architecture

`src/main.ts` mounts `App.vue` directly — **there is no router**. The site is one scrolling page and navigation is in-page anchor scrolling.

`src/App.vue` composes the page from section components and mounts the Sonner `<Toaster />`:

```
src/components/sections/
  SiteHeader.vue     sticky pill nav + mobile Sheet, highlight driven by scroll-spy
  HeroSection.vue    availability badge, name, CTA buttons, live GitHub graph
  WorkSection.vue    project cards + detail Dialog
  SkillsSection.vue  skill groups as Cards
  AboutSection.vue   intro copy + experience timeline
  ResearchSection.vue published paper card + PDF preview Dialog
  ContactSection.vue contact channels + EmailJS form
  SiteFooter.vue
```

**Content lives in `src/data/`, not in markup.** Adding a project means appending to `src/data/projects.ts` and dropping images into `public/images/`; adding a technology means one entry in `src/data/tech.ts` (the key is the [skillicons.dev](https://skillicons.dev) slug, the value is the badge label) and referencing that slug from a skill group or a project. `src/data/site.ts` holds the bio copy, contact details, EmailJS IDs, paper metadata and nav links.

`src/data/experience.ts` carries a `TODO(van)` — the timeline is derived only from claims the old site already made ("4 years... 3 in frontend..."). No employers or dates were invented; replace the entries when the real history is available.

### Supporting code

- `src/components/ui/` — shadcn-vue components. **Generated; regenerate with the CLI rather than hand-editing.** `components.json` configures the CLI (`style: new-york`, `baseColor: neutral`, `tsConfigPath: ./tsconfig.app.json`).
- `src/lib/utils.ts` — `cn()` (clsx + tailwind-merge), used by every generated component.
- `src/components/GithubContributions.vue` — the hero's right-hand panel. Fetches the real contribution history at runtime from `https://github-contributions-api.jogruber.de/v4/<user>?y=last` (no token, `access-control-allow-origin: *`), and paints it with the theme's own `--primary` at five opacities. **The hero therefore has a runtime network dependency**; the component handles loading and failure itself and degrades to a link to the GitHub profile, so a dead endpoint never leaves a hole in the hero. The username comes from `contact.githubHandle` in `src/data/site.ts`.
- `src/components/ScrollThread.vue` — the scroll rail, mounted once in `App.vue` beside `<main>`. A slim zigzag pinned to the **left edge** (`lg:` and up only) that doubles as navigation: each section (`top` plus every `navLinks` id) keeps its relative document position, mapped onto the rail's height, so the rail is a miniature of the page. A ghosted `--border` path shows the whole route under a `--primary` path revealed by `stroke-dashoffset` tied to scroll progress; nodes are real `<button>`s that call `scrollToSection()` and reveal a label on hover/focus, with the current one highlighted from `useScrollSpy()`. Under `prefers-reduced-motion` it renders fully drawn and attaches no scroll listeners.
- `src/composables/useScrollSpy.ts` — `useScrollSpy()` drives the nav highlight from an `IntersectionObserver`; `scrollToSection()` is the smooth-scroll helper. Replaces the old `vue-scrollto` directive.
- `src/directives/reveal.ts` — the global `v-reveal` directive (registered in `main.ts`, typed in `env.d.ts`). Takes an optional delay in ms: `v-reveal="120"`.
- `src/components/icons/index.ts` — the icon set. **Generated by `scripts/build-icons.mjs`; do not hand-edit.** Lucide ships ~1,800 icons across ~3,700 files and this site uses twelve, so the official Lucide outlines are inlined instead (plus the GitHub mark from Simple Icons, since Lucide v1 dropped brand icons). To add an icon, add it to the `STROKED` map in the script and re-run `node scripts/build-icons.mjs`.
- shadcn-vue components generated by the CLI import icons `from 'lucide-vue-next'` — after `npx shadcn-vue@latest add <component>`, rewrite those to `from '@/components/icons'` and add any missing icon to the generator.

## Styling

Tailwind **v4**, configured entirely in CSS — there is no `tailwind.config.js` and no `postcss.config.js`; `@tailwindcss/vite` is a Vite plugin. Everything lives in `src/assets/main.css`:

- Design tokens as oklch CSS variables on `:root`, mapped to utility names in `@theme inline`. The palette is a warm, low-chroma brown with a single amber accent.
- **The site is dark-only.** The dark values sit directly on `:root`, and `index.html` hardcodes `<html class="dark">` so shadcn components' `dark:*` utilities resolve.
- The old decorative `::before` background SVGs are gone (`home__header` / `skill__header` / `hire__header`), and so is the `.glow` radial wash that briefly replaced them — sections carry no decorative background.
- A fixed `body::before` paints the graph-paper grid behind the whole page (two `repeating-linear-gradient`s at a 48px pitch in `--border`, masked to a soft vignette). Fixed rather than on `body` so it never repaints while scrolling.
- `.reveal` / `.reveal-in` back the `v-reveal` directive; both no-op under `prefers-reduced-motion`.
- `.slide-next-*` / `.slide-prev-*` are the Work slider's direction-aware `<Transition>` classes; they flatten under `prefers-reduced-motion`.

Anything added to this file must go **inside a `@layer`** — Tailwind v4 emits real cascade layers, so unlayered CSS silently outranks every utility.

`@` aliases `./src` (declared in both `vite.config.ts` and `tsconfig.app.json`).

## Images

`public/` is what ships. Full-resolution originals live in `assets-src/images/` and are **not** published; `scripts/optimize-images.sh` (ffmpeg + libwebp) regenerates the served WebP set in `public/images/`, capped at 1200px wide. This took the published image weight from 21.4 MB to 1.2 MB, so do not add raw PNGs to `public/` — put them in `assets-src/` and re-run the script.
